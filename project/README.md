# Снежная дуэль — Unity / Android / Bluetooth Classic

Учебный прототип пошаговой дуэли для двух физических Android-телефонов. Проект находится целиком в этой папке. Существующая пояснительная записка вне проекта не изменялась.

## Открытие и сборка

1. В Unity Hub выберите **Add → Add project from disk**, укажите папку `project`.
2. Откройте в **Unity 6000.3.10f1 (Unity 6.3 LTS)**. У редактора должны быть модули Android Build Support, Android SDK & NDK Tools и OpenJDK.
3. Откройте сцену `Assets/Scenes/Duel.unity`. Она намеренно пустая: `DuelApp.Boot` создаёт приложение при запуске. Нажмите Play. В редакторе доступна кнопка **«Локальная проверка • 2 игрока»**: оба игрока управляются по очереди мышью; это не имитация работающего Bluetooth.
4. Выберите **Frost Duel → Build Android APK**. Команда сама задаёт сцену, Android Activity, IL2CPP, ARM64 + ARMv7, OpenGL ES 3, landscape, min API 27, target API 35 и отладочную подпись. Результат: `Builds/FrostDuel.apk`.
5. Для ручной сборки: **File → Build Profiles → Android → Switch Platform → Build**, со сценой `Duel` в списке. Настройки уже сохранены в проекте.

Сборка из терминала (закройте редактор, открывший этот проект):

```bash
/home/user/Unity/Hub/Editor/6000.3.10f1/Editor/Unity \
  -batchmode -nographics -quit \
  -projectPath /home/user/psu/psu7/coursework/project \
  -buildTarget Android \
  -executeMethod FrostDuel.Editor.ProjectBuilder.Android \
  -logFile /tmp/frostduel-build.log
```

## Запуск на двух телефонах

1. Требуются Android **8.1+**, Bluetooth Classic, поддержка OpenGL ES 3 и ARM64 либо ARMv7. Установите **один и тот же APK** на оба телефона. Wi-Fi, мобильный интернет и сервер не нужны.
2. Включите Bluetooth. На Android 8.1–11 включите также системную геолокацию для поиска устройств. На Android 12+ разрешите «Устройства поблизости»; геолокация приложению не нужна.
3. На первом телефоне нажмите **«Создать матч»**, выдайте запрошенные разрешения, подтвердите запрос видимости Bluetooth (до 300 секунд). Первый телефон становится ведущим и играет слева.
4. На втором нажмите **«Подключиться»**, выдайте разрешения, выберите имя и MAC-адрес первого телефона. При необходимости нажмите «Обновить поиск». Подтвердите сопряжение / одинаковый код на обоих устройствах. Второй игрок находится справа.
5. Если обнаружение не работает, сначала сопрягите телефоны в системных настройках Bluetooth, затем повторите пункты 3–4: сопряжённые устройства также отображаются в списке. Если Bluetooth включили после входа в экран, повторите ожидание или поиск.
6. После обмена полным состоянием начнётся матч. Ведущий выбирает seed и первого игрока. Оба телефона показывают текущий ход, здоровье, тепло, лёд и одинаковый рельеф.
7. Выберите **«Снежок»**, коснитесь игрового поля и проведите палец **вверх в сторону соперника**. Длина жеста определяет силу, наклон — угол. Отпустите в пределах поля для броска. Для отмены верните палец к началу жеста, уведите его за поле или нажмите «Отмена прицела». На правом телефоне жест направлен влево вверх.
8. **«Подготовить лёд»** сразу расходует ход и 10 тепла. Следующий ход принадлежит сопернику: его попадание уничтожает заготовку без возврата тепла. Если подготовка сохранилась, на вашем следующем ходу нажмите **«Бросить лёд»** и выполните жест. **«Утеплиться»** сразу завершает ход и восстанавливает тепло.
9. Ветер виден по снежинкам; метель усиливает снос снежка. При нулевом тепле персонаж и указатель дрожат; в начале собственных ходов мороз отнимает здоровье. Если достаточно долго не попадали, начинается пассивное восстановление тепла.
10. При нулевом здоровье появляется победитель. Вернитесь в меню на обоих телефонах для нового матча.

APK можно установить через USB:

```bash
adb devices
adb -s SERIAL_ПЕРВОГО install -r Builds/FrostDuel.apk
adb -s SERIAL_ВТОРОГО install -r Builds/FrostDuel.apk
```

## Разрыв и восстановление

Не закрывайте процессы игры. Если отключить Bluetooth, отойти за пределы связи или свернуть игру, действия блокируются; при молчаливом обрыве это занимает до 12 секунд. Ведущий сохраняет последний атомарно подтверждённый ход в памяти.

Включите Bluetooth и вернитесь в приложение. **Сначала на ведущем** нажмите «Повторить подключение», разрешите видимость, **затем на втором** нажмите «Повторить подключение». Ведущий отправит полный массив высот, seed, ход, погоду, здоровье, тепло и подготовку льда. Оба устройства продолжат после подтверждения снимка. Если соединение оборвалось во время полёта, после восстановления будет показан уже рассчитанный результат этого хода; повторного урона не будет.

Если Android уничтожил процесс, выполнен выход в меню или приложение принудительно закрыто, матч не восстанавливается: вернитесь в меню на обоих телефонах и создайте новый. Сохранения на диск и автоматический reconnect не реализованы.

## Баланс и структура

Все основные числа: **`Assets/Resources/Balance.asset`**, редактируются в Inspector. Класс и значения по умолчанию: `Assets/Scripts/Core/BalanceSettings.cs`. Ведущий передаёт свои настройки второму телефону при соединении. После изменения настроек пересоберите APK.

Начальный баланс — предложение для прототипа, а не окончательные требования:

| Параметр | Значение |
|---|---:|
| Здоровье / начальное тепло / максимум тепла | 100 / 50 / 100 |
| Снежок: здоровье / тепло цели | −8 / −22 |
| Подготовка льда | −10 своего тепла, один ход |
| Лёд: тело / голова / тепло цели | −35 / −60 / −8 |
| Утепление | +35 тепла |
| Пассивное восстановление | +6 в начале собственного хода после 2 собственных начал хода без попаданий |
| Мороз при нулевом тепле | −7 здоровья в начале собственного хода |
| Ошибка прицела от холода | до ±5° |
| Радиус воронки: снег / лёд | 0,85 / 1,35 |

Пассивное тепло и мороз дискретны по ходам: ожидание или скорость телефона не влияют на баланс. Попадание в голову льдом оставляет 40 здоровья у полностью здоровой цели. Самопопадание возможно при обратном сносе ветром. Утепление и снежок разрешены при уже подготовленном льде; он сохраняется до броска или попадания.

- `Scripts/Core`: `GameSession`, `PlayerState`, `TurnManager`, `Projectile`, `Snowball`, `IceProjectile`, `Terrain`, `WeatherController`; правила не зависят от UI.
- `Scripts/Network`: `BluetoothConnection` — адаптер BlueUnity, разрешения, поток байтов; `LineFramer` — разделение сообщений; `SessionCoordinator` — ведущий, действия, подтверждения, полные снимки.
- `Scripts/Presentation/DuelApp.cs`: экраны, сенсорный ввод, временные геометрические изображения, снег, анимация полёта и удара. Презентацию можно заменить спрайтами без изменения правил.
- `Plugins/Android`: BlueUnity AAR, Kotlin/Gson зависимости и manifest.
- `Editor`: настройка, сборка и проверки.
- `ThirdParty`: лицензии и сведения о включённых зависимостях.
- `Builds`: APK, отчёты проверок и материалы фактического запуска.

BlueUnity доступен под MIT и поддерживает нужные роли server/client, поэтому замена не потребовалась. Подробности версии, источников и известных особенностей: `ThirdParty/BlueUnity/PROVENANCE.md`.

## Проверки и ограничения

Фактические результаты и ограничения приведены в `Documentation/VERIFICATION.md`. Повторить автоматические проверки: **Frost Duel → Run core verification** (35 проверок) и **Frost Duel → Run protocol verification** (10 проверок). Они проверяют правила и сериализацию, но не заменяют испытание радиосвязи на телефонах.

Графика намеренно временная: геометрические фигуры и IMGUI, без готовых художественных ассетов и звуков. Ландшафт — разрушаемая линия высот; пещеры и нависающие поверхности не поддерживаются. Под персонажами остаются небольшие неразрушаемые опоры, чтобы фиксированные персонажи не зависали после воронок. Высокий снаряд обозначается у верхней границы поля. Таймера хода, ИИ, сохранений после завершения процесса и защиты от модифицированного клиента нет. Полноценный матч двух телефонов требует отдельного испытания на устройствах.
